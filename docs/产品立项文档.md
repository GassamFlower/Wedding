## 一、产品愿景

### 1.1 一句话定义

**让每一场婚礼都被看见** —— 通过 AI 技术，将婚礼策划从"经验驱动的手工艺"升级为"数据驱动的设计服务"，让策划师快速出方案、让新人所见即所得。

### 1.2 产品哲学

> "好的婚礼不应该只是有钱人的权利。"

我们相信：
- **可视化是信任的起点**：新人应该在签约前就看到婚礼的样子，而不是靠想象做决策
- **透明是专业的体现**：成本结构、利润空间、报价逻辑，都应该清晰可控
- **AI 是能力的放大器**：不是替代策划师，而是让一个策划师具备十个人的产能

## 二、市场机会

### 2.1 行业痛点

| 角色 | 核心痛点 | 现有解决方案 | 问题 |
|------|---------|------------|------|
| **准新人** | 签约前看不到效果，只能"信策划师的审美" | 口头描述 + 参考图 | 信息不对称，沟通成本高 |
| **准新人** | 不知道预算怎么分配 | 策划师经验估算 | 报价靠拍脑袋，利润不可控 |
| **策划师** | 反复跑场地、手写方案、靠经验估道具量 | Excel + 脑子记 | 一个人最多同时管 3-4 单 |
| **策划师** | 道具库存靠记忆，常常漏带或多带 | 纸质清单 | 损耗高、效率低 |
| **策划师** | 道具不足时无法快速获取市场租赁价格 | 手动搜索多平台 | 价格不透明、决策慢、成本高 |
| **行业** | 无专属数字化工具 | 通用 CRUD 系统 | 无法服务设计环节 |

### 2.2 市场空白

- **婚礼策划是高度依赖个人经验的手工艺行业**，从业者大量是中小工作室甚至个人策划师
- **市面无专属工具**：通用项目管理系统无法理解"道具折旧""花材底价""场景设计"等行业概念
- **AI 技术已成熟**：LLM 可以理解自然语言需求，生图模型可以渲染效果图，但行业尚未普及

### 2.3 目标市场规模

| 维度 | 数据 |
|------|------|
| 全国每年结婚登记 | ~700 万对 |
| 婚礼策划市场规模 | ~2000 亿元 |
| 武汉目标客群 | 每年 ~8 万对新人 |
| 渗透率目标 | 第一年 5%，第三年 20% |

## 四、用户画像

### 4.1 准新人（C 端）

**典型用户**：小林 & 小张，28 岁，刚订婚，开始筹备婚礼

**使用场景**：
- 刷到小红书婚礼案例，想看看"我的婚礼什么样"
- 不知道预算怎么分配合适
- 选酒店/选风格拿不定主意
- 希望签约前就能看到效果图

**没有这个工具之前**：
> 加了微信 → 约见面 → 聊需求 → 等几天出方案 → 不满意再改 → 再等几天……整个过程拉长到两周以上，而且全程看不到效果图，只能"信策划师的审美"。

**使用后的体验**：
> 打开小程序 → 和 AI 聊几句 → 3 分钟出方案 → 看到效果图和透明报价 → 满意就签约。整个过程不超过 10 分钟。

### 4.2 婚礼策划师（B 端）

**典型用户**：王策划，32 岁，独立婚礼策划师，武汉市区运营

**使用场景**：
- 早上打开工作台，看今天要跟进哪些线索
- 客户问了预算，直接 AI 出方案+报价
- 道具库存不足，系统自动提醒采购
- 场地搭建前，需要确认道具清单和利润
- **道具短缺时，快速查找线上租赁平台和市场价格**

**没有这个工具之前**：
> 靠 Excel 记账、靠脑子记库存、靠经验估算报价。利润算不准，道具常常漏带或多带。一个人最多同时管 3-4 个订单，多了就乱。**遇到大型婚礼或特殊道具需求时，只能临时联系多家租赁商，价格不透明、档期不确定，经常错过最佳采购/租赁时机。**

**使用后的体验**：
> 打开工作台 → 待跟进线索一目了然 → AI 自动生成方案+报价 → 成本利润自动核算 → 一键确认转合同 → **道具不足时直接查看市场参考价格，快速决策租赁或采购**。一个人可以同时管 8-10 单。

### 4.3 个人策划师/小团队（特殊场景）

**典型用户**：李策划，28 岁，刚入行的独立策划师，资金有限

**核心痛点**：
- **道具储备不足**：自有道具有限，经常缺少大量道具，无法突然购买
- **资金压力大**：无法一次性采购大量道具，需要灵活租赁
- **市场信息不对称**：不知道哪里租赁更便宜，缺乏价格参考

**使用场景**：
- 接到大型婚礼订单，需要大量道具但资金不足
- 需要特殊道具（如复古家具、定制花艺），本地市场找不到
- 想对比多家租赁商价格，选择最优方案

**解决方案**：
> 系统提供**道具市场数据参考**功能，整合线上租赁平台（淘宝、京东、闲鱼、本地租赁商）的价格和库存信息，策划师可以快速查找、对比、决策，降低采购/租赁成本。

### 6.3 登录与授权

> **核心策略**：浏览优先 + 功能触发登录。用户进入小程序可自由浏览案例、使用预算计算器等公开功能；点击需要登录的功能时，弹出登录授权弹窗。

#### 授权方式

| 方式 | 触发时机 | 获取信息 | 说明 |
|------|---------|---------|------|
| **静默登录** | 小程序启动时 | openid | wx.login 获取 code，云函数换取 openid，自动完成 |
| **微信授权登录** | 功能触发时 | 昵称 + 头像 | 弹窗引导用户授权，获取微信公开信息 |
| **手机号授权登录** | 功能触发时 | 手机号 | getPhoneNumber 组件，获取绑定手机号 |

## 九、产品价值

### 9.1 商业价值

**策划师产能翻倍**

过去一个人管 3-4 单，用 AI 方案+成本引擎后可以同时管 8-10 单。AI 自动生成道具清单和报价，方案从 3 天缩短到 3 分钟。每单利润透明可控——道具折旧、花材底价、人工日薪、运输费用全部自动计算，策划师只需确认和微调。

### 9.2 效率提升

**把"先收钱再出方案"变成"先看方案再买单"**

新人打开小程序，和 AI 聊几句就自动生成可视化方案和透明报价。签单前就能看到效果图、婚礼海报、迎宾区 KT 板效果——转化率远超传统"加了微信慢慢聊"模式。策划师端项目看板统一管理线索、订单、道具、合同，不再多系统切换。

### 9.3 社会价值

**降低婚礼策划行业的数字化门槛**

婚礼策划是一个高度依赖个人经验的手工艺行业，从业者大量是中小工作室甚至个人策划师。这个工具让"一个人+一部手机"就能具备专业设计能力。免费的海报和 KT 板效果图，让预算有限的新人也能拥有一场精心设计的婚礼——**好的婚礼不应该只是有钱人的权利**。

## 十二、开发边界与范围约束

### 12.1 开发边界定义

> **核心原则**：聚焦婚礼场景策划垂直领域，不做通用项目管理工具

#### 明确包含（In Scope）

| 类别 | 范围 | 说明 |
|------|------|------|
| **用户角色** | 准新人 + 婚礼策划师 | 双角色系统，通过邀请码切换 |
| **业务场景** | 婚礼场景策划全流程 | 获客→设计→报价→签约→执行→复盘 |
| **核心功能** | AI 设计对话 + 方案生成 + 成本引擎 | 三大核心能力，支撑快速出方案 |
| **数据管理** | 订单/客户/道具/酒店/合同 | 婚礼策划相关业务数据 |
| **道具市场** | 外部租赁平台价格参考 + 数据集管理 | 帮助策划师实时获取市场道具价格，辅助租赁/采购决策 |
| **内容运营** | 案例展示 + 文章发布 | 支撑获客和品牌建设 |
| **AI 能力** | LLM 对话 + 生图渲染 | DeepSeek + 通义万相/Stable Diffusion |

#### 明确排除（Out of Scope）

| 类别 | 排除内容 | 原因 |
|------|---------|------|
| **业务领域** | 非婚礼策划业务（如活动策划、会议服务） | 垂直聚焦，避免功能膨胀 |
| **用户角色** | 供应商管理（花艺师、灯光师等外部角色） | 当前阶段聚焦策划师和新人 |
| **功能范围** | 通用项目管理（甘特图、任务分配等） | 不做通用工具，专注婚礼场景 |
| **支付功能** | 在线支付（微信支付）| v3.1 计划，当前版本不包含 |
| **社交功能** | 新人社区、策划师论坛 | 当前聚焦工具属性，不做社交 |
| **多语言** | 英文、其他语言支持 | 当前仅服务武汉本地市场 |
| **移动端** | App、H5 版本 | 仅微信小程序，降低开发成本 |

### 12.2 功能优先级矩阵

| 优先级 | 定义 | v3.1 功能 | 开发策略 |
|--------|------|----------|---------|
| **P0** | 核心功能，必须实现 | 场景渲染 Agent | 立即开发，阻塞上线 |
| **P1** | 重要功能，强烈建议 | 效果图标注、编排 Agent、RAG 知识库、成本看板、微信支付、**道具市场数据采集工具** | 优先排期，1-2 个月内完成 |
| **P2** | 锦上添花，可选 | 场地档案升级、方案分享卡片、智能排期 | 资源允许时开发 |
| **P3** | 未来规划，暂不考虑 | 供应商管理、新人社区、多语言 | 记录需求，不排期 |

### 12.3 技术边界约束

#### 必须遵守

| 约束 | 说明 |
|------|------|
| **微信生态** | 仅使用微信云开发，不引入第三方后端服务 |
| **技术栈锁定** | Monorepo 架构：Taro (React) + Next.js 14 + Ant Design Pro，不引入新框架 |
| **AI 服务** | LLM 使用 DeepSeek（主）/ OpenAI / 通义千问（备），生图使用通义万相 / Stable Diffusion |
| **设计系统** | 必须遵循轻复古·奶油风设计语言，禁止使用纯灰、Material Design 阴影、冷色蓝灰 |
| **数据安全** | 用户数据存储在微信云数据库，不导出到第三方 |

#### 禁止行为

| 禁止 | 原因 |
|------|------|
| ❌ 引入 React、Angular 等其他框架 | 技术栈已锁定，避免维护成本 |
| ❌ 使用第三方后端（如阿里云、腾讯云） | 已选定微信云开发，保持一致性 |

### 13.4 成本核算流程

```
┌─────────────────────────────────────────────────────────────┐
│                    成本核算流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① 输入参数                                                  │
│     ├── 道具清单（propList）：名称/数量/来源（自有/租赁）       │
│     ├── 花艺需求：主桌花/餐桌花/路引花/手捧花等                │
│     ├── 人工需求：策划师/工程主管/工人/花艺师/管家              │
│     ├── 场地信息：桌数/场地类型/距离                           │
│     └── 其他：消耗品/保险/损耗准备金                          │
│     ↓                                                       │
│  ② 硬成本计算                                                │
│     ├── 道具折旧：自有道具 × 折旧单价（如竹节椅 ¥3/次）         │
│     ├── 道具租赁：租赁道具 × 市场租赁价                        │
│     ├── 花材采购：各花材 × 采购底价                           │
│     ├── 消耗品：硬成本 × 2%                                   │
│     ├── 保险：¥200/次                                        │
│     └── 意外损耗：硬成本 × 3%                                 │
│     ↓                                                       │
│  ③ 人工成本计算                                               │
│     ├── 策划师：¥800/人天 × 天数 × 人数                       │
│     ├── 工程主管：¥600/人天 × 天数 × 人数                     │
│     ├── 婚礼管家：¥500/人天 × 天数 × 人数                     │
│     ├── 搭建工人：¥400/人天 × 天数 × 人数                     │
│     └── 花艺师：¥600/人天 × 天数 × 人数                       │
│     ↓                                                       │
│  ④ 运营成本计算                                               │
│     ├── 运输：按道具总量估算车型 × 2 趟                        │
│     │   └── 小面 ¥150 / 中面 ¥300 / 大车 ¥600                │
│     └── 平台：LLM ¥0.5 + 图片生成 ¥2 + 云服务 ¥0.5 ≈ ¥3/次   │
│     ↓                                                       │
│  ⑤ 利润计算                                                  │
│     ├── 总成本 = 硬成本 + 人工成本 + 运营成本                   │
│     ├── 利润 = 总成本 × 利润率（默认 35%）                     │
│     ├── 客户报价 = 总成本 + 利润                               │
│     ├── 利润率 = 利润 / 客户报价                               │
│     └── 毛利率 = 利润 / 总成本                                 │
│     ↓                                                       │
│  ⑥ 报价区间生成                                               │
│     ├── 最低报价 = 总成本 × 1.20                              │
│     ├── 标准报价 = 客户报价                                    │
│     └── 品质报价 = 总成本 × 1.55                              │
│     ↓                                                       │
│  ⑦ 输出双层定价                                               │
│     ├── 客户视图：4 项简洁大类（场景/花艺/策划/运输）            │
│     └── 策划师视图：全部成本明细 + 利润 + 报价区间               │
│                                                             │
│  边界情况处理：                                                │
│  ├── 桌数为 0 → 按最低标准（10 桌）计算                        │
│  ├── 预算不足 → 提示"预算低于成本，建议调整方案"                │
│  ├── 道具数量为 0 → 跳过该项计算                               │
│  └── 租赁道具 → 使用市场租赁价，不计折旧                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

| 会员管理 | ✅ 查看自己的 | ✅ 查看自己的 | ✅ 全部 |

**数据隔离规则**：策划师只能看到自己创建的数据（orders/clients/leads/contracts），通过 `createdBy` 字段过滤

#### 方案确认规则

| 规则 | 说明 |
|------|------|
| 方案必须存在 | `proposalId` 必须有效且状态为 `draft` |
| 客户必须已登录 | 通过 `wx.cloud.getWXContext()` 获取 openid |
| 订单自动创建 | 方案确认后自动创建 order，状态为 `pending` |

| 方案状态更新 | 方案状态从 `draft` → `confirmed` |
| 会话状态更新 | 会话状态从 `proposal_ready` → `confirmed` |
| 不可重复确认 | 已确认的方案不能再次确认 |

| 来源 | 成本计算 | 库存管理 | 说明 |
|------|---------|---------|------|

| `rental`（租赁） | 市场租赁价 × 使用次数 | 不扣减库存 | 参考 prop_market_references 数据集 |
| `market`（市场采购） | 采购价 | 增加库存 | 新购道具，计入库存 |

## 十四、验收标准与质量要求

### 14.1 功能验收标准

#### AI 设计对话

| 验收项 | 标准 | 测试方法 |
|--------|------|---------|
| 多轮对话 | 支持至少 10 轮连续对话，上下文不丢失 | 手动测试 10 轮对话 |

| 响应时间 | 首次响应 < 2 秒，后续响应 < 3 秒 | 压力测试 |

## 二十二、总结

### 22.1 产品定位

**大喜的日子** 是一个 AI 驱动的婚礼场景设计协作平台——策划师上传场地照片，AI 生成效果图；新人用自然语言描述梦想婚礼，AI 输出可视化方案和透明报价。

### 22.2 核心价值

- **对策划师**：产能翻倍，从管 3-4 单提升到 8-10 单；方案从 3 天缩短到 3 分钟；利润透明可控
- **对新人**：3 分钟出方案，签约前就能看到效果图；透明报价，明白消费
- **对行业**：降低数字化门槛，让"一个人+一部手机"就能具备专业设计能力

### 22.3 差异化优势

- **垂直于婚礼场景策划行业**：懂道具折旧、花材底价、场景设计
- **AI 原生**：不是传统系统+AI 功能，而是 AI 驱动的全新工作流
- **双层定价**：客户看简洁，策划师看透明
- **已实际运营**：不是 PPT 产品，而是已经在武汉线下运营的团队

## 二十五、产品阶段路线图

> 战略藐视战术重视，分阶段推进。避免一次性铺开所有功能。

| 阶段 | 时间 | 核心目标 | 功能范围 | 成功指标 |
|------|------|---------|---------|---------|
| **v1.0 验证期** | 0-3 月 | 验证核心价值：AI 方案 + 成本引擎 | 小程序新人端（3 Tab）+ 策划师端（4 Tab）+ 管理后台基础版 | 完成 10 单真实成交，NPS > 30 |
| **v1.5 效率期** | 3-6 月 | 提升策划师效率，跑通业务闭环 | 成本引擎优化 + 订单全流程 + 道具市场数据 + 合同管理 | 策划师产能提升至 6 单/月，利润率 > 25% |
| **v2.0 增长期** | 6-12 月 | 规模化获客，AI 能力升级 | AI 场景效果图 + Web 官网 + 免费增值（海报/KT板） | 累计 100 单，付费转化率 > 5% |
| **v3.0 壁垒期** | 12-18 月 | 建立数据壁垒与行业口碑 | 数据飞轮（案例积累→AI 质量提升→更多案例）+ 开放 API | 武汉市场占有率 5%，策划师社群 50+ 人 |

**阶段决策原则**：
- 上一阶段未达指标，不进入下一阶段
- 每个阶段结束时进行复盘，调整下一阶段计划
- v1.0 聚焦小程序双端，Web 官网延后至 v2.0
