## 1. 设计系统

### 1.1 设计语言

**风格定义**: 轻复古·奶油风 — 暖白基底 + 香槟金点缀

**设计关键词**: 温柔、精致、治愈、呼吸感、质感

**色彩比例**:
- 暖白基底 (#FFF9F2): 60%
- 纯白卡片 (#FFFFFF): 20%
- 香槟金点缀 (#D4AF37): 12%
- 辅助色: 8%

### 4.2 API 接口规范

#### 通用请求格式

```javascript
// 云函数入口
exports.main = async (event, context) => {
  const { action, data } = event;
  
  try {
    const result = await handlers[action](data);
    return { code: 0, data: result };
  } catch (err) {
    return { code: -1, message: err.message };
  }
};
```

#### 通用响应格式

```javascript
// 成功
{ code: 0, data: { ... } }

// 失败
{ code: -1, message: "错误描述" }

// 列表查询
{ code: 0, data: { list: [], total: 0, page: 1, pageSize: 20 } }
```

### 5.2 数据关联

```
orders ←→ clients (clientName 关联，订单记录客户名称)
orders ←→ contracts (orderId 关联，合同关联订单)
orders ←→ todos (orderId 关联，待办关联订单)
leads ←→ orders (orderId 关联，线索转化后生成订单)
schedule ←→ orders (weddingDate 关联，排期基于订单日期)
schedule ←→ hotels (date 关联，排期检查酒店冲突)
```

### 5.3 集合使用规范

#### 核心原则

1. **一实体一集合**：每个业务实体拥有独立的集合，不混用
   - `orders`：仅存储订单数据
   - `clients`：仅存储客户数据
   - `hotels`：仅存储酒店数据
   - `props`：仅存储道具数据
   - `contracts`：仅存储合同数据

2. **跨集合引用**：通过 ID 或名称关联，不在集合内嵌套其他实体的完整数据
   - 订单通过 `clientName` 关联客户
   - 合同通过 `orderId` 关联订单
   - 待办通过 `orderId` 关联订单

3. **汇总查询允许跨集合**：统计类操作可以跨集合读取
   - `dashboard` 汇总：读取 orders/contracts/leads/todos 统计
   - `hotels.summary`：读取 orders 统计押金信息
   - `schedule`：读取 orders/hotels 检查冲突

#### 各云函数集合映射

| 云函数 | 主集合 | 跨集合读取 | 说明 |
|--------|--------|-----------|------|
| orders | orders | - | 订单 CRUD |
| clients | clients | - | 客户 CRUD |
| hotels | hotels | orders, todos | 酒店 CRUD + 押金汇总 + 待办 |
| props | props | todos | 道具 CRUD + 待办 |
| contracts | contracts | - | 合同 CRUD |
| leads | leads | - | 线索 CRUD |
| schedule | - | orders, hotels | 排期查询（跨集合） |
| dashboard | - | orders, contracts, leads, todos | 数据汇总（跨集合） |
| search | - | orders, props, hotels, contracts, todos | 全局搜索（跨集合） |
| cases | orders | - | 案例展示（从 orders 筛选 isCase=true） |
| todos | todos | - | 待办 CRUD |
| knowledge | knowledge | - | 知识库 CRUD |
| ai-chat | design_sessions | - | AI 会话记录 |
| proposal-generator | proposals | orders, contracts | 方案生成 + 创建订单/合同 |
| user | users | - | 用户管理 |
| budget | budgets | - | 预算 CRUD |
| articles | articles | - | 文章 CRUD |
| images | images | - | 图片管理 |
| seed-data | - | orders, clients, props, hotels, knowledge | 初始化种子数据 |

#### 禁止行为

- ❌ 在 clients 云函数中写入 orders 集合
- ❌ 在 orders 云函数中写入 clients 集合
- ❌ 将客户信息完整嵌套在订单中（应通过 clientName 关联）
- ❌ 在非汇总类云函数中跨集合写入

#### 允许行为

- ✅ 汇总类云函数（dashboard/schedule/hotels.summary）跨集合读取
- ✅ 通过 ID 或名称关联查询
- ✅ seed-data 初始化多个集合
- ✅ proposal-generator 创建订单和合同（业务流转）

## 6. 开发约束

### 6.1 命名规范

#### 文件命名

- 页面目录: `pages/[page-name]/`
- 页面文件: `[page-name].js`, `[page-name].wxml`, `[page-name].wxss`, `[page-name].json`
- 组件目录: `components/[component-name]/`
- 云函数: `cloudfunctions/[function-name]/`

#### CSS 类名

- 使用小写 + 连字符: `order-card`, `action-btn`
- 状态修饰: `--active`, `--disabled`, `--done`
- 尺寸修饰: `-sm`, `-md`, `-lg`
- 颜色修饰: `-gold`, `-pink`, `-green`

#### JavaScript

- 变量: 小驼峰 `clientName`, `orderList`
- 常量: 大写下划线 `MAX_RETRY_COUNT`
- 函数: 小驼峰 `loadData()`, `submitForm()`
- 事件处理: `on` 前缀 `onLoad()`, `onTap()`

### 6.2 样式约束

#### 必须遵循

- ✅ 使用 CSS 变量（`var(--gold)`）
- ✅ 使用 rpx 单位（小程序）
- ✅ 使用全局定义的共用组件类
- ✅ 页面级样式仅覆盖必要属性

#### 禁止事项

- ❌ 禁止硬编码颜色值（`#D4AF37` → `var(--gold)`）
- ❌ 禁止使用 `!important`
- ❌ 禁止在页面级重复定义全局组件
- ❌ 禁止使用内联样式（除动态计算外）
- ❌ 禁止使用 `px` 单位（小程序必须用 `rpx`）

### 6.3 API 约束

#### 必须遵循

- ✅ 统一使用 `callOrDefault` 调用云函数
- ✅ 统一响应格式 `{code, data, message}`
- ✅ 列表查询必须支持分页 `page/pageSize`
- ✅ 错误必须返回 `{code: -1, message: "..."}`

#### 禁止事项

- ❌ 禁止在前端直接操作数据库
- ❌ 禁止在云函数中硬编码敏感信息（使用环境变量）
- ❌ 禁止返回未过滤的用户隐私数据

### 6.4 组件约束

#### 图标使用

- ✅ 必须使用 SVG 背景图实现
- ✅ 必须使用全局定义的图标类
- ❌ 禁止使用字体图标
- ❌ 禁止使用图片图标（除特殊场景）

#### 卡片使用

- ✅ 优先使用全局 `.card` 类
- ✅ 变体使用 `.card-compact`, `.card-warm` 等
- ❌ 禁止自定义卡片基础样式

### 6.5 性能约束

- 图片必须压缩（< 200KB）
- 列表必须分页（每页 ≤ 20 条）
- 云函数执行时间 < 3s
- 避免在 `onLoad` 中执行耗时操作
